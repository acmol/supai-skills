# 数据目录、记忆与限额

## Task 工作区

每个 Task 有独立的工作区（`/workspace`）、会话状态和传输目录。
- `/stop`、空闲超时：全部保留，之后发消息即恢复。
- `/clear`、stop 超期自动 clear：工作区被清空，不可恢复。
- 所以**需要长期保留的东西不要只放在 /workspace**。

## 用户数据目录 /data

- 每个用户一个永久目录，在容器内固定为 `/data`，该用户名下**所有 Task（含子 Task）共享**，不同用户互不可见。
- 在该用户的第一个 Runner 启动时自动创建；存量用户无需操作。
- 持久化：`/stop`、`/clear`、stop 超期自动 clear、Runner 重建、平台升级/重启都**不会**动 /data；平台不会自动删除（只有管理员可显式删除）。
- 没有属主的 Task 没有 /data。创建/挂载失败时 Task 仍能启动，但本次没有 /data（Agent 会被告知，不应把长期记忆写进 /workspace），下次启动会重试。

### 长期记忆：/data/memory/*.md

- 把偏好、长期约定等写成 Markdown 放在 `/data/memory/`，每次 Runner 启动（新建或 stop 后恢复）都会读取并加入 Agent 的上下文；运行中修改下次启动才生效。
- 直接对 Agent 说“记住……”，它会写到这里；也可以让它编辑/删除条目。
- 规则：只读目录下直接子级的 `.md` 文件（不递归、忽略 `.` 开头文件和符号链接）；按文件名排序，最多 16 个；单文件 16 KiB、总计 48 KiB，超出部分被截断/跳过。大资料放 `/data/` 下其他位置（如 `/data/notes/`），由 Agent 按需读取。
- 记忆内容是用户自己的输入，没有任何平台特权，不能改变权限，平台规则冲突时以平台规则为准。
- `/workspace/AGENTS.md` 之类是 Task 级项目说明，**不是**记忆，会随 clear 丢失。

### 配额

- 默认每用户 **1 GiB**（软配额，管理员可调，0 为关闭检查）。
- 在 Runner **启动时**检查：用量 ≥ 配额时 /data 变为**只读**（已有记忆仍会加载，但不能写），Agent 会提示你清理。清理后下次 Task 启动恢复读写。
- 已知限制：运行中的 Task 仍可能超额写入，直到下次启动才被发现。
- 用户自助清理：让 Agent 在 Task 里 `du -sh /data/*` 查看并删除不需要的文件。

## 其他限额（默认值，管理员可调）

| 项 | 默认 |
|---|---|
| 同时存活（running+idle）的 Task | 10 |
| 空闲自动 stop | 3600 秒 |
| stop 后自动 clear | 30 天 |
| Runner 内存 | 2g |
| 用户发给平台的单个文件 | 50 MB |
| Agent 发回飞书的单个文件 | 30 MB |
| 单条语音转写时长 | 300 秒 |
| 每会话未结束的定时任务 | 20 |
| 回复过长时 | 自动分段，标注 (i/n) |

## Task 环境变量

可在 Web 管理端的 Task Settings 里查看/设置/删除，Agent 也可用平台操作 `list_task_env` / `set_task_env` / `delete_task_env`。平台保留的名字不能设置（以 `SUPAI_`、`COPILOT_`、`GIT_`、`LD_`、`SSL_CERT_` 开头的，以及代理等少数固定名字）。
