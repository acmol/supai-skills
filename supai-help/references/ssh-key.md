# SSH 密钥

## 概念

- **每个用户一把**平台生成的 ed25519 密钥，首次查看（`/ssh` 或 Web 页）时生成，之后一直复用。私钥加密保存，**任何界面都不会显示私钥**，只给公钥和指纹。
- 公钥注释是“姓名 <企业邮箱>”（取不到则降级为姓名，再不行为 `supai-user`），不含 open_id。
- **默认开启**“Task 内使用私钥”：私钥以只读文件挂载进你自己的所有 Task（路径 `/run/secrets/ssh_key`，已配置 ssh 默认使用，无需 `-i`）；关闭后 Task 里拿不到私钥。
- 修改开关后，运行中的 Task 约一个控制器周期内同步；新启动的 Task 按当时设置。
- 用户从未查看过密钥时，启动 Task 不会生成密钥。

## 飞书命令（仅属主；群里他人发的无效）

| 命令 | 作用 |
|---|---|
| `/ssh` | 显示公钥、指纹和“Task 内使用私钥”状态（没有则先生成） |
| `/ssh on` | 开启 Task 内使用私钥（默认已开） |
| `/ssh off` | 关闭 |
| `/ssh regen` | 只提示后果，不执行 |
| `/ssh regen confirm` | 重新生成：旧密钥**立即失效**且无法恢复 |

使用方法：把 `/ssh` 回复里的整行公钥追加到目标服务器的 `~/.ssh/authorized_keys`。

## Web

`/web/ssh-key` 页面提供同样功能：复制公钥、重新生成（需二次确认）、开关、审计记录。只能操作自己的（管理员也不能看别人的）。

## 重新生成之后

平台只能让旧**私钥**失效，**服务器上 `authorized_keys` 里的旧公钥不会被自动删除**：重新生成后需要自己在所有放过旧公钥的服务器上删除旧公钥、加入新公钥。

## 风险提示（回答时务必带上）

- 开启时容器里的 Agent 能读取私钥；若 Agent 被 prompt injection 诱导，可能把私钥外传。
- 建议：只把公钥放到可接受风险的机器，或只读权限的账号；不用时 `/ssh off`；怀疑泄露立即 `/ssh regen confirm` 并更换服务器上的公钥。
- Agent 可调用平台操作 `get_my_ssh_key` / `regenerate_my_ssh_key`（后者需确认）；没有“开启私钥”的工具，开关只能由用户本人在飞书/Web 操作。

## 排障

- 回复“SSH 密钥功能暂不可用”：平台的密钥加密存储不可用，请联系管理员。
- Task 里没有私钥：检查开关是否关闭（`/ssh`）、是否已生成过密钥、该 Task 是否有属主；然后让 Task 重新启动（`/stop` 后再发消息）。
- ssh 连不上：Task 只能经平台的 HTTP 出口代理上网，目标服务器须能被该出口访问，细节请联系管理员。
