# 写好给用户看的报告（publish_report）

目标：用户打开报告，**第一屏就知道结论**，不用读术语堆，一眼能看懂图。

## 五条规矩

1. **结论先行**：第一屏（`:::summary` 卡片）三五句人话：做了什么 / 结果怎么样 / 需要用户做什么（没有就写“无”）。
2. **说人话**：少用行话和缩写；必须用的术语紧跟一句解释；能打比方、举例子就别抽象陈述。
3. **多图**：流程用 `flow`，数量对比用 `bars`，占比用 `pie`，关键数字用 `kpi`，方案对比用表格；有截图 / 示意图就用 `data:` 图片或内联 SVG。**别写文字墙**。
4. **结构**：摘要 → 关键结论 → 细节（日志、代码、长清单放 `:::details` 折叠）→ 未验证项 / 需要你做的事。
5. **手机能读**：用 `format=markdown` 或 `fragment`，平台主题已处理好（响应式、深浅色、宽表格横向滚动、长代码自动折叠）。自己写整页 HTML 才需要手动加 viewport。

## 用法：format=markdown（推荐）

`publish_report(title=..., html=<Markdown 正文>, format="markdown")`。标题不用在正文再写一遍（页面已有 h1）；正文里 `#` 标题会显示成二级标题。

| 语法 | 效果 |
|---|---|
| `:::summary` … `:::` | 开头的“先看结论”卡片 |
| `:::note` / `:::warn` / `:::ok` … `:::` | 蓝 / 橙 / 绿提示卡 |
| `:::details 标题` … `:::` | 折叠块 |
| ```` ```flow ````：每行 `A -> B -> C` | 流程图（每行一条，窄屏自动换行） |
| ```` ```bars ````：每行 `名称: 数值` | 横向数据条（按最大值归一） |
| ```` ```pie ````：每行 `名称: 数值` | 饼图 + 图例（内联 SVG） |
| ```` ```kpi ````：每行 `指标: 值` | 数字卡片 |
| 表格、列表、`- [x]` 待办、引用、`` `代码` ``、链接、`![图](data:image/png;base64,...)` | 常规 Markdown；原始 HTML 会被转义；链接只允许 http(s) / mailto；图片只允许 `data:image/`（页面不能联网） |

## 骨架（交付报告）

````markdown
:::summary
**做了什么**：一句话。
**结果**：通过 / 部分完成 / 受阻，一句话原因。
**要你做的**：1 件具体的事（没有写“无”）。
:::

```kpi
测试: 全绿
PR: #123
改动文件: 8
```

## 做法一图看懂
```flow
用户请求 -> 平台校验 -> 生成页面 -> 返回链接
```

## 方案对比
| 方案 | 好处 | 代价 | 结论 |
|---|---|---|---|
| A | 简单 | 慢 | 不选 |
| B | 快 | 要改 3 处 | **选这个** |

## 关键结论
- 结论 1（一句人话 + 依据）
- 结论 2

:::details 测试与 CI 详情
五项检查结果、命令、关键日志片段……
:::

## 未验证项与风险
- [ ] 手机浏览器没测

:::warn
需要你做的：……
:::
````

## 需要自定义版式：format=fragment

`html` 只写 `<body>` 里的内容，平台加外壳与同一套主题。可用类：`summary`、`card`、`callout note|ok|warn`、`kpis` 里放 `kpi`（`<b>值</b><span>名称</span>`）、`flow`（`<span class="n">步骤</span><span class="a">→</span>…`）、`bars`、`details`。仍可内联 `<svg>` 画自己的示意图。

## 发布后

返回的 `hints` 是非阻塞提示（没结论 / 没图表 / 太长没折叠 / 没小标题 / html 格式缺 viewport 或样式）。能改就用 `replace_report_id` 覆盖重发，链接不变。
