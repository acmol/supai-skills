# 飞书命令与消息

## 基本规则

- 命令必须在消息**开头**，区分大小写；中间出现的 `/xxx` 或未知的 `/xxx` 都是普通文本。
- `/stop` `/clear` `/status` `/esc` 必须是整条消息（不带其他文字）。
- 命令只对 **Task 属主** 生效。群里其他成员发的命令按 untrusted 普通文本处理。
- 命令不会产生给 Agent 的消息，由平台直接回复。
- 命令在哪个位置发，就作用于哪个 Task：会话主入口 → 根 Task；子 Task 的话题里 → 该子 Task。
- **平台没有 `/help` 命令。** 想看用法可以直接问 Agent（用本手册），`/timer`、`/ssh` 发不带参数或参数错误时会回复用法。

## 普通消息

直接发文字、图片、文件、语音即可。
- 普通消息排队，Agent 按顺序处理。Task 是 stop 时会自动恢复。
- 语音：自动转写（带 🎙️ 标记，可能有识别误差），原音频作为附件。超过 300 秒（默认）或转写失败时降级：消息仍送达，带失败原因和原音频。
- 附件：用户发给平台的文件默认最大 50 MB；Agent 通过平台发回飞书的文件最大 30 MB。

## 命令清单

| 命令 | 谁能用 | 作用 |
|---|---|---|
| `/status` | 属主 | 查看当前 Task：编号、标题、状态、排队数/执行中数、最近错误、退出意图。不刷新活跃时间 |
| `/esc` | 属主 | 中断**正在运行**的这一轮（Agent 停止当前工具调用），Task **不退出**，回到 idle，上下文保留。不是 running 时回复“无需中断” |
| `/steer <内容>` | 属主 | 在 Task 运行中立刻插入一条指示（立即投递）；Task 不是 running 时等同普通消息。不带内容只回复用法 |
| `/stop` | 属主 | 停止 Task（容器停止，工作区/会话/历史保留；之后发消息自动恢复）。已不是 idle/running 时回复无需停止 |
| `/clear` | 属主 | **清空** Task：工作区被清理，不可恢复（消息历史记录保留）。用户的 `/data` 不受影响 |
| `/task <需求>` | 属主 | 新建子 Task（飞书里新开话题）去做这件事。并发满了会提示“运行中的任务已达上限，请稍后再试或先 /stop 其他任务”；当前 Task 已清空时会提示失败 |
| `/connect github` | 属主 | 发起 GitHub 授权（Device Flow）：回复一个链接和验证码，在浏览器打开并输入即可授权。授权后 Task 里的 `git` 访问 github.com 会用你的授权 |
| `/ssh` | 属主 | 查看/管理你的平台 SSH 密钥，详见 [ssh-key.md](ssh-key.md) |
| `/timer ...` | 属主（管理已有的也可由管理员） | 定时任务，详见 [timers.md](timers.md) |
| `/restart-service [分支]` | 仅管理员 | 从 GitHub 拉取并重新部署平台。普通用户使用会被拒绝；**不要代为执行，请用户联系管理员** |
| `/deploy-status [N]` | 仅管理员 | 查看当前运行的版本和最近 N 次部署 |

要点：
- `/stop` 与 `/clear` 的区别：stop 可恢复，clear 不可恢复。想“暂时不用了”用 `/stop`；想“彻底丢掉这个 Task 的文件”才用 `/clear`。
- `/esc` 与 `/stop` 的区别：`/esc` 只打断这一轮、Task 继续存活；`/stop` 让整个 Task 退出。
- `/steer` 与普通消息的区别：普通消息排队等当前回合；`/steer` 尽快插入。已开始的工具不保证被撤销。
- 在 Web 管理端的聊天窗里也可以发 `/steer` `/stop` `/esc`（见 [web.md](web.md)）。`/ssh`、`/restart-service`、`/deploy-status`、`/timer` 在 Web 消息里不可用，会提示改用飞书或 Web 页面/平台操作。

## 会话与话题

- 主入口发的消息 → 根 Task；子 Task 话题里的消息 → 该子 Task。
- 子 Task 已被 clear 后，在它的话题里发消息会回到主 Task，并附带提示（Agent 可用 `get_task_output` 查看该话题的历史用户消息）。
- 子 Task 完成后会向父 Task 回报结果（`submit_result`）。
